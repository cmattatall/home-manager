HOW TO REVIEW                                                *rediff-workflow*

1. Open rediff in a Git checkout (or Space r). j/k in the tree previews files.
   Tab enters the diff. ]/[ moves between hunks; :fs/:fu switches Git groups.
2. Read red deletions and green additions. :view toggles split/merged layout.
   Press i to add/edit a note, or select lines with V then a for a range note.
3. Write the note, Esc then :w to save it locally. @ lists/searches saved notes.
4. :harness use amp connects to your local agent (see |rediff-harness| for setup).
   :w from the tree/diff sends saved notes. :ho opens an agent terminal.
5. As the agent edits, files refresh. Violet ◆ means changed/unseen; cyan ◇ means
   changed/seen after 1s in the focused diff. See |rediff-git| for baseline rules.
6. Stage deliberately with s (hunk) or S (file); sending notes never stages code.
   Space R refreshes now. Space q leaves Review for ordinary editing.

REVIEW AND ANNOTATIONS                                          *rediff-review*

Interactive startup without file arguments opens Review inside Git, with tree
focus and a diff preview. File arguments open directly for editing.
Moving onto a file previews it. Tab enters the diff. Space q returns to editing,
with the launch directory's explorer ready after automatic Review startup.
Outside Git, startup stays in ordinary editing without a sidebar.
Headless runs open neither Review nor the tree. Space r toggles Review.
The bottom bar shows the branch (or detached @short-SHA), harness and delivery.

BRANCH DIFF MODE

:git diff BASE TARGET compares two commits, with BASE on the OLD side and
TARGET on the NEW side. Use full/short SHAs, branches, tags, or refs like HEAD~2.
For example: :git diff main HEAD or :git diff a1b2c3d e4f5a6b.
Typed :gd BASE TARGET is a shortcut, in Review or ordinary editing.
Scripts should use :Git diff. Normal-mode gd still finds symbol definitions.
Tab completes base and diff; other Git subcommands are not supported.
This is an exact endpoint diff, not a merge-base (three-dot) comparison.
Both refs are resolved to fixed SHAs when opened. Space R refreshes those same
commits; run :git diff again to pick up a moved branch. Local staged, unstaged,
and untracked changes are excluded. Renames appear as a deletion and addition.
Split/merged views, file/hunk navigation, filtering, and annotations work as in
Review. Staging, reverting, and :fs/:fu are unavailable here. :Review returns to
worktree changes; Space q leaves for editing. Notes retain their commit snapshots.

:git base BASE changes only the base of the current comparison, preserving its
pinned target SHA. Without a commit comparison, it compares BASE against the
current HEAD. For example: :git base HEAD~3. It never checks out a commit or
changes local files/index. Scripts should use :Git base BASE.

Right-click a path in either tree and choose Copy Relative Path from the context
menu to copy its repository-relative path to the system clipboard. Outside Git,
paths are relative to the filesystem explorer's root. Opening or dismissing the
menu does not copy anything; headers and blank rows omit the option.

In Normal mode, Cmd+C copies the relative path and Ctrl+Shift+C copies the full
path from either tree or a Review diff pane. Trees use the selected row; diff
panes use the displayed file. Headers and blank tree rows do nothing. Your terminal
must forward these keys to Neovim instead of using them for terminal text copying.

ANNOTATING ORDINARY FILES

Space a (or :AnnotationMode) toggles annotation mode for the current named file
inside a Git checkout, including clean files and unsaved edits. The bottom bar
shows ANNOTATE. While enabled, source text is protected and the same controls,
note composer and harness delivery used by Review apply: i adds/edits a note;
v/V/Ctrl-v then a annotates an exact selection; d deletes a note; @ lists notes.
Esc in the source (Normal mode), or Space a again, restores normal editing and
any previous buffer-local mappings when no note editor is open. Esc never closes
an open note or exits annotation mode while that note is open.
From a harness or unnamed pane, Space a returns to the single visible annotated
file and exits annotation mode. It does not guess between multiple annotated
files or use a file from a different harness checkout; focus the source first.
Review always has annotation mode on; Space a does not turn it off there.

:w in the note saves the note locally and closes it. Then :w or :write in the
annotated source sends saved notes through the selected harness, without writing
source edits. :w in its harness pane also sends when a single annotated source
is visible. :WriteFeedback is the explicit send command. Leave annotation mode
with Space a or Esc before using :w to save source edits. With no configured or
running harness, feedback is queued locally. Notes are shared with Review in
this editor process.

Notes retain the exact buffer text at annotation time, including unsaved edits.
Later edits never move their anchors. Jumping to a note on another or older
snapshot opens its protected Review view; it does not overwrite the file.
If an external reload changes the buffer text, annotation mode turns off; use
Space a again to annotate the new text. Notes/drafts remain in this process.

Source panes are protected snapshots. Editing commands open a note instead of
changing code. i edits the note under the cursor; overlapping notes open a picker.
:annotations new always creates a separate note. For an exact range, select with
v/V/Ctrl-v, then a (also i or Space c). The harness receives the selection's range
and character/block columns, not just the cursor line.

The note editor floats below the selected range without resizing the diff panes.
Notes use normal Neovim editing. Esc while typing returns to Normal mode.
Further Escape presses leave the note open. Use :q to close and retain its draft.
  :w / :wq        Save locally and close
  :q / :q!        Close and keep the draft
Reopen the same line/range to resume its draft.

Saved notes appear as orange text under their source range. Orange >> in the gutter
marks notes at the cursor. @ searches filenames and note text; Enter jumps, Esc
cancels. i edits that note. } / { cycles in creation order across files/sides;
counts work (3}). d deletes a note, not source or already-sent feedback. These
bindings leave ordinary files/note text unchanged.

A file with saved notes has an orange ● at the right edge of its tree row.
Both rows are marked if the file appears in STAGED and UNSTAGED. The dot includes
notes on older snapshots and disappears when the file's last note is deleted,
archived, or cleared after successful delivery.

A violet ◆ (changed since annotated) marks notes whose annotated lines changed
on their selected side. Edits elsewhere, including line-number shifts, do not
mark notes or trigger the submission warning. Insertions inside a selected range
count as changes. The note border stays orange; restoring the source clears the
badge. Checks also run while a note is open, without changing its text or anchor.

Jumping to an older note shows its original snapshot and pauses refresh/staging.
Space R returns to current files. Old-side notes switch merged view to split.
Editing a note preserves its anchor. :w in diff/tree sends the saved notes.
An empty batch shows "No agent notes to send to the harness".
See |rediff-drafts| for retention and retry.

GIT AND REFRESH                                                    *rediff-git*

Ordinary files show Gitsigns gutter marks against Git's index, including unsaved
edits: green for additions, yellow for modifications, and red for deletions.
Untracked files get green dashed marks. Review snapshots keep their own diff
rendering; Gitsigns does not attach to them. GitGud remains the blame provider.

gitgud provides one interface in ordinary files and Review source panes:
  Space g b / :GitGud blame-line   Show author, date and commit for this line
  Space g B / :GitGud blame        Browse blame for every source line
  Space g i / :GitGud toggle       Toggle inline blame for the focused line
  Space g p / :GitGud pr           Show this line's associated PR links

:gitgud is a typed alias for :GitGud. Tab completes subcommands. :GitGud without
arguments toggles inline blame, just like :GitGud toggle. :GitGud blame-toggle
remains an alias. In blame views, p shows the selected line's PRs; in full-file
blame, Enter returns to that source line. q/Esc closes the view.
Full-file blame is read-only and keeps your editor/Review layout intact.

The popup displays HTTPS links with terminal hyperlinks (OSC 8). Use your local
terminal's link-click modifier, usually Cmd-click on macOS; no browser command
runs on the remote SSH host. q/Esc closes; y on a URL yanks it to Neovim's unnamed
register. Terminal selection/copy works too. Wrapped links remain hyperlinks in
terminals supporting OSC 8; terminal/tmux settings may affect click handling.
PR lookups require gh authentication on the machine running Neovim (gh auth login).
Missing PRs and lookup errors are reported in the popup, never silently ignored.

Review blames the selected OLD/NEW snapshot, not the current on-disk file. Normal
editing includes unsaved buffer contents. New/uncommitted lines have no commit
or PR. Merged-view red deletions are virtual lines: switch to split view and use
the OLD pane to blame them. Closing a loading popup discards late results.

Inline blame is on by default. Use Space g i or :GitGud to toggle it. It follows
the focused source line after CursorHold, clears when you move/edit, and discards
stale asynchronous results. It annotates the end of the line without replacing
source text.

The local gitgud Lua plugin also works without Rediff: copy lua/gitgud/ into your
Neovim config's lua/ directory and call require('gitgud').setup(). It is tested
with the bundled Neovim 0.12 and Git 2.54; gh is needed only for PR lookups.
Rediff supplies snapshot context through setup's context() callback: return
{root,path,head,text,side?}, where path is repo-relative, head is a
pinned commit SHA (empty for unborn HEAD), and text is the exact snapshot.
Return nil to use normal file-buffer discovery. No Gitsigns dependency.

STAGED compares HEAD/index; UNSTAGED compares index/worktree and includes untracked
files. Badges: M modified, U untracked, R rename, A added, D deleted. Partially
staged files appear in both groups. h/Left collapses a group (▸); l/Right or Enter
expands it (▾) and restores its selected file. Enter never collapses a group.
j/k or Up/Down moves between visible files
and collapsed or empty group headers, skipping blank rows. The selected header
is highlighted. Refresh preserves collapsed groups;
:fs/:fu and hunk navigation reveal their target file.

In the file tree, / filters files in place. Enter applies; Esc cancels.
To clear, press /, Ctrl-u, Enter. Matching is case-insensitive by default:
  nix                 Filename contains "nix"; parent directories do not count
  *.nix               Filename glob; only files ending in .nix
  nix/                Path contains "nix/"
  nix/*.py            Path glob; Python files directly in nix/
  nix/**/*.py         Path glob; Python files anywhere under nix/
  re:\.nix$           Regex; filenames ending in .nix
  re:^nix/.*\.py$     Regex against the repository-relative path
Patterns containing / match paths; otherwise they match filenames only.
Globs support *, **, ?, [], and {a,b}, matching the whole name/path. Other
unprefixed text is a literal substring. re: uses Vim very-magic regex syntax
(\v); escape regex metacharacters with a backslash. Invalid patterns leave the
previous filter unchanged.
The active filter appears below the tree title; counts and file/hunk navigation
use matching entries. The filter survives refresh and staging until Review closes.
/ in source panes still searches text. Space f opens a separate fuzzy picker.

Change awareness (automatic, for this editor session):
  Violet ◆       Changed since the last accepted send, not yet seen; pulses for 2s
  Cyan ◇         Changed since that send, already seen
  No diamond     Matches the baseline or was acknowledged by staging/unstaging
Hunks use matching labels and line-number colors; red/green still mean delete/add.
A hunk becomes seen after 1s visible in a focused diff pane, not a tree preview.
A successful s/S clears the affected hunk indicators in either group. Moving them
back does not restore purple; new edits do. Other unread hunks stay unread.
A file stays unseen while any changed hunk is unseen. This records exposure, not
approval. The baseline starts with Review's initial contents.
Accepted local-harness sends reset the baseline to pre-send contents;
failed/local-only sends do not. Changes are detected
on refresh regardless of who edited them. Paths no longer in Git's diff leave the
tree. Context-only line shifts do not count as new hunks. No manual marks to manage.

] / [ wraps through hunks within the current group; counts work (3]). :fs / :fu
switch groups without changing pane focus. Space j/k moves files across groups.
Ctrl+Shift+] / Ctrl+Shift+[ does the same but skips seen and baseline hunks.
It works in the tree and either diff pane, preserves focus, and reports when no
unseen hunks remain. Use Space R first when viewing an older annotation snapshot.
Kitty and tmux must forward the modified brackets. If needed, add to kitty.conf:
>
  map ctrl+shift+[ send_text all \x1b[91;6u
  map ctrl+shift+] send_text all \x1b[93;6u
<
And to tmux.conf:
>
  bind-key -n C-S-[ send-keys -l "\033[91;6u"
  bind-key -n C-S-] send-keys -l "\033[93;6u"
<

s in a source pane toggles its Git hunk; S toggles the selected/displayed file.
UNSTAGED stages; STAGED unstages. These actions apply immediately, change only
the index, and reject stale snapshots. Inside ordinary files/notes, s/S still
edit text. An all-green new file is one hunk: s stages it and advances to the next
unstaged hunk (or unstages it from STAGED). Empty/deleted files need S; renames
use delete/add pairs.

r in either source pane immediately discards the Git hunk at the cursor.
Select a range with v/V/Ctrl-v then r to discard all Git hunks it intersects,
including their context lines. :ReviewRevert does the same and accepts a line
range; find it in Space p / :Commands. This is not partial-line deletion.
UNSTAGED reverses changes on disk, leaving the index alone. STAGED reverses
the selected hunks in both index and worktree, but refuses files with unstaged
edits: unstage first in that case. New files are one hunk (discard deletes them);
discarding a deleted-file hunk restores it. Empty/mode-only files have no text
hunk. Unsaved file buffers, stale snapshots and historical annotation views
block the action. Existing notes keep their original snapshots.

Discard notifications are separate from annotation drafts. They batch for 750ms
while the connected agent is running (also unknown/offline), or 5s while idle.
The window starts at the first discard; further discards do not extend it.
An agent becoming active shortens an idle window. A delivery already in flight
finishes first. Notifications tell the agent which hunks were already discarded
and to re-read the files instead of reapplying them.

Pending discards survive leaving Review or restarting the editor; reopening
Review resumes pending batches. Failed/uncertain sends are not retried silently.
:ReviewRevertFlush sends now or explicitly retries the oldest pending batch;
:ReviewOutbox contains its saved context and receipts. Batches stay bound to the
original harness; reselect it before flushing after switching agents. Discards
made with no harness stay local until you connect one and explicitly flush.

After staging, selection advances within the original group. Whole-file actions
use the previous file at the end; hunk actions wrap to the next remaining hunk.
An exhausted group stays empty instead of following the file into the other group.
Git may combine nearby displayed changes into one staging hunk.

Connected Amp file-edit events trigger refreshes in this worktree. Polling every
three seconds catches other edits/index changes. Refresh runs with Normal-mode
tree/diff focus, preserves selection/focus, and pauses for
annotation editing, typing, selections, commands, pickers and delivery.
Typing in an embedded harness terminal does not pause refresh.
Notes keep their original snapshots.
Space R / :ReviewRefresh refreshes immediately without sending feedback.
Use it instead of :bufdo e: Review panes are snapshots, not ordinary file buffers.
Outside Review, :checktime checks loaded files for external changes.

Set programs.rediff.reviewRefreshInterval in Home Manager, or add
"review_refresh_interval": 10 to settings.json in stdpath('config') (normally
~/.config/rediff). Use a whole number of seconds; 0 disables fallback polling.
Apply your Home Manager configuration, or save settings.json if not managed by
Home Manager, then leave/re-enter Review (Space q, Space r).
Amp file events and Space R still work with polling disabled.

AGENT HARNESSES                                               *rediff-harness*

For a running Amp session, use :harness install amp once, then :harness connect amp.
The installer enables Ctrl-L and Esc Esc for thread.interrupt in
~/.config/amp/settings.json for all Amp sessions for this user. Rerun it after
upgrading from the Ctrl-L-only setup. Other settings/keybindings are preserved.
Home Manager-managed settings must be updated in Home Manager.
For oh-my-pi (OMP), use :harness install omp, then /restart in OMP and
:harness connect omp. Home Manager can manage the CLI (programs.harnesses.omp.enable)
and extension (programs.rediff.ompPlugin.enable) independently. Upstream pi is not
supported. OMP feedback is admitted asynchronously, not acknowledged as completed.
Session switches replace its connection; select the new session in rediff.
After a cancelled switch, /rediff-connect in OMP resumes feedback delivery.
Use :harness use amp to select Amp and connect in this worktree. Connecting sends
nothing. :harness use omp selects OMP. :hc opens the connection panel;
:hl / :harness list opens the same
searchable panel for all available sessions. Each row shows its worktree directory;
long paths are shortened in the list, with the full path in the selected details.
The open panel discovers sessions every second; closing it stops polling.
Amp may run in another terminal emulator or tmux session on this machine under
the same user account. Load the readiff plugin in each Amp instance. Remote
machines and orbs are not discoverable through this local connection.
  /           Filter by alias, provider, title, ID, worktree, or activity
  Enter       Connect/disconnect; connecting locally selects the annotation target
  o           Open highlighted harness in the harness pane
  C           Hide highlighted harness's terminal without stopping it
  n           Start a fresh harness in this worktree (prompts for type)
  r / d       Rename locally / disconnect selected harness
  D           Delete selected instance from this editor's list (asks first)
  c / R / q   Connected-only filter / rediscover / close

:harness delete <id> also deletes a listed instance, with confirmation.
Deletion disconnects feedback, clears its local alias, and removes the row. It
does not stop the agent terminal, delete its thread, or touch worktree files or
annotations. Automatic discovery will not restore that connection in this editor;
R explicitly rediscovers deleted live instances. A new connection (after an agent
restart) or a new editor can also discover it again. Deletion is blocked while
feedback is being sent from the current or selected worktree.

The [open] badge marks the terminal visible in this tab, not the highlighted row
or annotation target. Hidden terminals have no badge. Opening reuses an existing
editor terminal and keeps other connections. A session from another worktree
opens in its own directory without changing this review's annotation target.

:harness close hides this worktree's terminal pane in the current tab, keeping its
process and feedback connection alive. C in the list hides only the selected
harness. Reopen it with :harness open or o in the list.

:harness new [amp|omp|claude] starts a fresh CLI in the current worktree, not a
resumed session. Omitted type prompts, even when a launch type is already saved.
The list's n opens the same prompt, including with no entries. Cancellation
changes nothing. The CLI must be installed/authenticated separately. Other
terminals and connections stay alive; the previous feedback target is cleared.
Connect the new session before sending notes. The chosen type is saved locally.

Multiple harnesses can stay connected. Annotations only go to this worktree's
selected harness; :w from the tree/diff sends them. To type to an editor-owned
agent, use :harness open (below); external Amp/Claude sessions ask before resuming
in the editor. Connecting for feedback alone leaves their original terminal alone.
Separate editors can watch the same agent.
Amp streams running/idle/approval/error state and active tool names to the panel.
Offline or unsupported activity is shown as such, never inferred from an ACK.
Aliases persist locally; connection subscriptions end when this editor exits.

:harness open (alias :ho) opens the current worktree's harness.
While loading, a spinner appears and keyboard input is discarded (not queued).
Loading times out after ten seconds, restores input, and ignores late results;
run :Harness open again to retry. Provider/session choices and resume confirmations
remain interactive and do not count toward the loading timeout. Input resumes as
soon as the terminal or activity panel opens; CLI login/startup happens there.
A single connected/editor-owned harness opens directly. Multiple local candidates
show a chooser even if one is already selected.
Without a session or configured provider, it asks which harness to start and saves
that provider for the worktree. Cancelling starts nothing.
Other worktrees are excluded. Opening a connected session selects it for annotations.
An editor-owned TUI reuses its terminal split, process and buffer. Explicitly
opening an external Amp/Claude session asks before starting its CLI in the pane.
Stop using its other terminal first: this resumes the thread in a new TUI, not
an attachment to the existing process. Cancelling starts nothing.
The bridge carries annotations and activity, not terminal screen or keyboard input;
OMP remains activity-only because session resumption is unsupported.
After disconnecting, open rediscovers live sessions even after an editor restart
or when opening a file instead of Review. With no live match, the Amp adapter
checks saved history before starting fresh; other adapters retain their launch behavior.
While typing in an Amp pane, Ctrl-C hides it like :harness close,
keeping the process and feedback connection alive. Use
:harness open to return to the same terminal. Ctrl-L twice still interrupts Amp.
After Amp exits, open offers to resume the saved thread in a
new TUI. Automatic startup only connects to an existing live session; it does not
start another CLI for it.
The shared startup policy for every harness is: connect to a live session in this
directory/worktree, otherwise resume the last recorded session, otherwise start
fresh. Discovery, validation, and resume commands are provider-adapter concerns.
The full sequence currently has an Amp implementation; OMP/Claude support is
pending, not an intended difference in policy.
With the current Amp adapter, bare interactive startup connects to a live thread
in this exact worktree without launching another CLI. Its terminal stays where
it is. If several threads match, the last recorded one wins, or a picker asks
you to choose.
If none is live, startup resumes the last recorded thread; only missing/invalid
history starts a fresh CLI. The Amp plugin stores history per canonical workspace
under $XDG_STATE_HOME/rediff/amp (default ~/.local/state/rediff/amp), including
threads started outside Neovim. Empty welcome screens have no thread ID yet.
A confirmed missing ID is invalidated; auth/network/active-elsewhere errors retain
history and stop startup. Resume errors stay visible in the terminal and never
silently launch a replacement. Reconnection keeps checking while the resumed CLI
runs, including during network recovery. Exiting the CLI or explicitly changing
or disconnecting the harness stops those checks. Use :harness connect amp to
connect manually.
Missing CLIs leave Review usable.
File/directory arguments, headless runs, and none/custom harnesses do not auto-open.
Space r moves an open harness pane between Review and editing, keeping its
window, buffer, and process. Hiding it in either mode keeps it hidden across
toggles until :ho reopens it.

Escape returns control to Neovim in the same pane (Terminal-Normal mode), without
sending Escape to the harness. Repeated Escape does not interrupt the agent.
With the harness pane focused, the mouse wheel scrolls the harness UI in both
input and Terminal-Normal modes, provided the harness enables mouse reporting.
Scrolling in Terminal-Normal mode leaves Neovim in control; i still resumes input.
Use Cmd-W then an arrow to switch panes, or i to resume harness input. In Amp panes,
Ctrl-L sends Escape to dismiss menus, pickers, and dialogs, in both input and
Terminal-Normal modes without changing modes. Press Ctrl-L twice to interrupt
the agent after :harness install amp configures it. Standalone Amp still accepts
single Ctrl-L to interrupt. Other harnesses keep their native Ctrl-L behavior.
Cmd-W p returns to the previous editor window from Terminal mode, leaving the
TUI running. Cmd-W also accepts other window commands, such as h/j/k/l. Ctrl-W
passes through to the TUI for word deletion, including repeated presses.
Ctrl-\ Ctrl-N enters Terminal-Normal mode; :hide hides the pane; :ho brings it back.

Amp text copying uses Neovim's clipboard provider via terminal OSC 52 writes,
not the SSH server's desktop clipboard. Copy-only xclip/wl-copy/pbcopy wrappers
are scoped to Amp panes, not ordinary shells or Neovim's own PATH. Over SSH,
the host terminal must support clipboard writes (directly or through tmux).
Reading the local clipboard from the remote process is not enabled.

In Review, press Escape then type :w (or :write) from its harness pane to send
the saved annotation batch, just as from the tree or diff panes. This shortcut
applies only to the active Review's own worktree, not to ordinary terminals.

The bridge cannot move an external TUI into Neovim. :harness resume first
rediscovers the selected session: a live local match reconnects without launching
a CLI, and a match in another worktree blocks launch. Without a live match, it
confirms before starting a TUI for a saved Amp or Claude session.
Open also offers this confirmation for saved sessions without a live bridge.
Stop using the other terminal first. This does not create a new thread, attach to
or kill its process, or send a prompt. OMP session resumption is not supported here.
Resumed live Amp sessions reconnect feedback when their plugin registers a fresh
endpoint for the same thread and worktree. Until then, annotations remain saved;
retry :w after the connection is ready.

Fresh embedded Amp terminals automatically bind feedback after the first thread
starts. Update the bundled Amp plugin with :harness install amp and reload it in
Amp after upgrading the editor. Launch identity distinguishes this terminal from
other Amp processes in the same checkout. Explicit target changes cancel pending
automatic binding. A configured/open but unconnected harness blocks :w with a
"nothing sent" message and keeps the notes; it never silently falls back to the
local outbox. Local-only review requires no configured/running harness. Keep the
editor open while reconnecting: unsent notes remain process-local. Retry :w once
the target is connected.

Plugin installation asks for confirmation, preserves Home Manager symlinks, and
does not install/authenticate the Amp CLI. With a live target, it also requests
an agent-mediated reload; queued does not mean reloaded. Without one, reload Amp
manually once. Reconnect afterwards. Live install/connect supports Amp only.

CLI continuation is a separate transport; select an explicit session:
  :ReviewHarness amp T-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
  :ReviewHarness claude SESSION_ID
  :ReviewHarness custom
  :ReviewHarness none

These bindings persist per worktree. Authenticate the CLI separately and stop any
other process driving that session. This does not synchronize remote workspaces
or bypass agent permissions. Custom receivers use programs.rediff.feedbackCommand
or feedback_command in settings.json; they receive a JSON path and must acknowledge
its submission ID. See nix/README.md for installation and receiver details.

WORKTREES                                                  *rediff-worktrees*

:worktree list opens the management pane. The current checkout is marked *.
In the list:
  j/k         Select worktree
  Enter       Switch to selected worktree
  n           Prompt for new branch, create worktree, and launch harness
  dd          Confirm deletion and stop editor-owned harness jobs
  R           Refresh list
  q / Esc     Close list

:worktree switch and :worktree delete open action-specific pickers when no
branch/path is supplied. Enter switches or confirms deletion; j/k, R and q/Esc
select, refresh and close. These pickers have no create/delete management shortcuts.

:harness use amp|omp|claude selects the launch type for this worktree.

:worktree new [branch [path]] creates from current HEAD and starts that harness in
a bottom terminal split. Omitted branch prompts; omitted path uses a sibling directory.
The CLI must already be installed/authenticated. Existing branches/paths are never
forced. A launch failure keeps the worktree; inspect its terminal and :messages.
Ctrl-\ Ctrl-N leaves Terminal mode; :hide hides the pane. Editor exit stops its
terminal processes. Switching alone never launches a harness.

:worktree delete [branch|path] deletes a linked checkout, keeping its branch and
saved review metadata. It stops only harness jobs launched by this editor, never
external or merely connected agents. The main checkout, locked/unavailable trees,
another editor's live review, unsaved file buffers, and staged/unstaged/untracked
files prevent deletion. Git removal is never forced (ignored files follow Git's
normal behavior). Deleting the current checkout switches to the main one first.
If Git refuses removal after a harness stops, the checkout is retained.

New worktrees inherit launch type, not connections or drafts. Dirty files and
saved notes stay with their checkout; save/close an open note before switching.
Switching preserves a saved harness selection, or connects a single live session
in that exact worktree for its selected type (either live provider if unset).
No match or multiple matches never open a picker during switching.
Changing harness type disconnects incompatible bindings but retains notes.

==============================================================================
PANES AND VIEW                                                   *rediff-view*

:view split shows old/new panes; :view merged shows deleted rows above new text.
:view toggles while retaining file/hunk and notes. Merged deletions are virtual:
use split for exact old-side selections. Old-side search/note jumps do this for you.

  Space E               Toggle filesystem tree; focus-only in Review
  Cmd-w h/j/k/l         Focus adjacent pane (macOS); Cmd-w w cycles
  gt / gT              Next/previous tab
  :setlocal [no]number  Show/hide line numbers
  :setlocal [no]wrap    Wrap/unwrap text

In a Review diff pane, :set wrap / :set nowrap (also :setlocal) applies to both
panes. The choice survives file changes, refreshes, and split/merged switches.
Ordinary editing windows, the tree, and note editors keep their own wrap setting.

Cmd-w is a prefix, then a direction (arrows or h/j/k/l), also from harness input.
Kitty must forward Command keys explicitly. In kitty.conf: >
  map cmd+w send_text all \x1b[119;9:1u
<
The explicit press event (:1) preserves Command through tmux 3.6 instead of
normalizing it to Alt. Reload Kitty after changing its configuration.
Normal/Visual Ctrl-w window navigation is disabled; Insert Ctrl-w still deletes
a word. Closing a required source pane exits Review.

Additions are green, deletions red. Difftastic supplies structural token highlights;
text highlights remain on failure/timeout or files over 1 MB. Git defines staging
hunks regardless of rendering. The bottom bar names the active diff tool.

==============================================================================
ORDINARY EDITING                                              *rediff-editing*

Normal Neovim editing applies outside protected source panes. Space f searches
project files; Space / searches saved contents. In Review these search changed
entries and both snapshot sides, including deletions. Enter chooses; Esc cancels.
/ and n/N search the current buffer, except / in the Review file tree filters
paths. ? opens this guide; use :? for backward search.

Tabs and indentation default to four spaces (expandtab, tabstop=4, shiftwidth=4).
Filetype and project settings may override these defaults.

Space s / :Symbols opens Telescope's current-file symbol picker; Space S /
:WorkspaceSymbols searches workspace symbols as you type. Use them from an
ordinary source buffer with an attached language server that supports symbols,
not a Review snapshot. Enter jumps to the selected symbol; Esc closes the picker.
:Telescope lsp_document_symbols and :Telescope lsp_dynamic_workspace_symbols
are also available. File/text search continues to use the existing pickers.

Opening a directory (for example, rediff src) uses the filesystem explorer.
Its Git markers are green A for added, green U for untracked, and yellow M for
modified. Directories summarize changes inside them, even when expanded. Deleted
files are absent from this explorer; they remain available in Review.

In a Review source pane, Option+Enter (Alt+Enter / gd) finds definitions of the
symbol under the cursor using Neovim's LSP client. Results open in a separate
editing tab; multiple matches also open the quickfix list. gT returns to Review
without losing notes. Lookup is asynchronous and never edits source, stages,
or sends feedback.

Nix bundles nvim-lspconfig and servers for Lua, Nix, Python, JS/TypeScript,
Go (gopls), and Rust (rust-analyzer). Go and Rust use your project's toolchain;
provide go or cargo/rustc on PATH. Nix supplies Rust standard-library sources;
set RUST_SRC_PATH to use sources matching a different project toolchain.
The Nix server automatically fetches missing flake inputs. A statusline spinner
shows "Fetching flake inputs" while it works; editing remains available.
Configure your terminal to send Option+Enter as Alt/Meta+Enter; use gd if it
sends plain Enter instead. Insert-mode editing is unchanged.

Ctrl-a / Ctrl-e moves to line start/end in Insert and command/search input.
Option+Left/Up/h/k moves a word backward; Option+Right/Down/l/j moves forward.
Set your terminal's Option key to Alt/Meta; Esc-b/Esc-f sequences also work.

For native navigation/editing, see :help motion, :help editing, :help undo,
:help registers and :help windows. File-tree actions: |neo-tree-mappings|.

==============================================================================
DRAFTS AND DELIVERY                                            *rediff-drafts*

Accepted/completed delivery deletes sent notes but preserves newer edits.
Failed, pending and local-only batches stay in this process. Leaving/re-entering
Review retains drafts; exiting discards them without an unsent-note quit guard.
Every fresh editor starts empty. Submitted payloads/receipts persist in the outbox.

You can keep editing while the agent responds.
One delivery per worktree may be in flight. Typing drafts does not write to disk.
Keep the editor running during delivery. "accepted" means queued; "completed"
means the turn finished, not that its changes are correct. Inspect the session
and receipt before retrying uncertain delivery. Retries use the original payload.
Without a binding, submissions stay local. Credentials never belong in Nix/Git.

After a failure, :w keeps the notes without resending or raising a Lua error.
:Harness status shows the saved failure reason and recovery advice. Check the
agent before :ReviewRetry; a closed connection requires :harness connect amp/omp.

Built-in harnesses receive JSON: rules once, then context and annotations.
There is no prose prefix or epilogue. Explicit Git/PR authorization in your
feedback or earlier conversation messages carries forward within its scope;
the agent must not ask again. A commit request includes staging relevant changes
unless you limit it to already-staged changes. Other Git/PR actions still require
authorization. Exact ranges and snapshot status remain. Source/patches stay in
the private outbox, referenced by path; custom receivers get the full payload.
Choose your receiver carefully.

LIMITS                                                        *rediff-parity*
Binary files, merge conflicts and files over 2 MiB are unsupported. Notes are
not re-anchored automatically. File/hunk annotation scopes, LSP inspection
and collapsed/compact diffs are not implemented. See FEATURES.md for the inventory.
